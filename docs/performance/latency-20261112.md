# Latency verification — 12 November 2026

Application changes were deployed to https://examination-system-saa.vercel.app through commits `b9923d7`, `9a444e6`, and `569363a`.

## Changes

- Load the PowerPoint parser only on authorized paper uploads. Initialize native slide rendering and fonts only inside the rendering worker, rather than during ordinary Express startup.
- Start independent workspace page requests alongside their lookup lists. Catalog-only pages still wait for their own records; role scoping and the workspace-owned lookup cache remain intact.
- Prepare the signed CSRF token while the login page is open. Submission shares the in-flight request and retries failed preparation. Reuse a valid signed cookie so opening another login tab does not invalidate existing forms.
- Serve fingerprinted public assets with `public, max-age=31536000, immutable`. HTML and all private API responses retain `no-store`. Fresh administrator page proof, database-backed account checks, rate limits, and bcrypt cost remain enforced.

## Measurements

| Users-page API workflow | 1,591.40 ms | 783.07 ms | Median of six alternating serial/parallel pairs in one live authenticated session; about 51% lower |

The paired production comparison warms both paths first, then alternates order. It compares the former sequential centers-then-users request path with the new parallel path against the same deployed APIs. It measures completion of HTTP requests, not browser paint. One earlier paired run aborted on a TLS `ECONNRESET`; it produced no completed dataset and was repeated once. The raw successful run retains all six pairs, including a slower parallel outlier.

Separate three-sample before/after deployment snapshots were noisy: median sign-in was 1,438.66 ms before and 2,080.21 ms after; overview was 747.39 ms before and 950.12 ms after. These do **not** establish a live login or overview speedup. Local import measurements are not hosted cold-start measurements. Preparing CSRF removes that request from the submit critical path only when preparation has completed before submission.

Production checks after `569363a` confirmed:

- `/login`: HTTP 200 and `Cache-Control: no-store`.
- Its fingerprinted JavaScript: HTTP 200 and `Cache-Control: public, max-age=31536000, immutable` (previously `public, max-age=0`).
- Reissuing CSRF with the existing valid cookie returns the same token.
- Unauthenticated administrator overview: HTTP 401 and `Cache-Control: no-store`.
- Earlier authenticated production checks also rejected an administrator request without its page proof and denied administrator access to examiner authoring APIs.
